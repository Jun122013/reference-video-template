# 如何写新的提示词

> 作者：胡峻

## 先选路线

| 路线 | 适合情况 | 要检查的限制 |
|---|---|---|
| T2V：文字生成视频 | 不需要锁定具体身份或首帧，文字能表达场景 | 身份、布局、时序随机性 |
| I2V：首帧生成视频 | 需要固定人物、服装、构图或初始空间关系 | 首帧必须适合后续动作；过紧构图会阻碍全身运动 |
| R2V / 多参考 | 需要多图身份、场景、风格或动作参考，工具支持 | 每份素材的角色与冲突；各平台对该名称定义不同 |
| 源视频编辑 | 用户要求保留源时序/运动且允许输入原视频 | 必须有真实源视频编辑能力，不能与普通多参考混称 |

“参考原片做分析”不等于“把原片上传模型”。用户不允许输入原视频时，只用获准图片/音频等资产和文字。接口没有某种能力就写明，不虚构字段；注册资产成功也不代表生成权限已通过。

垫图要解决具体问题。若需要，图像 Prompt 写清主体身份/外形约束、服装、动作起始姿态、镜头、构图、光照、脚下承重、前后景关系和输出画幅。不要把不同镜头的互斥状态塞在一张首帧里。

## 将拆解变成新内容

先写“固定 / 替换 / 改进”清单，再写目标事件表。改变时长时保留关键动作的准备和落稳空间，重新安排事件，不能仅按比例压缩并承诺动作还能成立。

每个重要变化都表达：

**谁在什么空间状态 → 做什么可见动作 → 动作哪一阶段触发变化 → 镜头如何配合 → 落到什么状态 → 怎样接下一段。**

信息优先级：用户硬约束、关键机制、动作与空间连续性、必要美术，再到装饰。多项互相矛盾时先解决冲突；增加形容词不能抵消参考冲突。

## 参数化母版

这是给人复用的版本，可以保留变量：

```text
目标：{{画幅}}、{{时长}}的{{视觉目标}}。
主体：{{人物或产品}}。需保持{{身份/形态约束}}。
参考依赖：{{素材清单及各自角色，或无需参考}}。
固定机制：{{动作—转场—声音的关键关系}}。
变化内容：{{场景/服装/文案等可替换槽}}。
时间结构：{{开场、变化段、高潮、收尾的目标窗口}}。
空间互动：{{承重、遮挡、共同透视等实际需要}}。
声音方案：{{保留原声/生成/替换/静音及执行方式}}。
避免：{{最相关的具体失败}}。
```

另附槽位约束：输入是什么、允许变化、不能破坏什么。例如“城市可换，但每城需一个能建立尺度的地标和可落脚空间”。没有试过换城，不声称已经验证任意城市。

## 本次可提交实例

填完所有变量，移除不适用项，写成自然、明确的连续指令。不要保留“同上、参考里的那个”等依赖上下文的词。

可按下列顺序组织，不要求每条片都使用全部段落：

1. 输出与目标效果。
2. 实际传入参考的分工：图1仅约束身份，图2约束场景等。
3. 开场状态及首个动作。
4. 目标时间窗口中的动作、变化与镜头衔接。
5. 共同光照、承重、遮挡等关键空间关系。
6. 结尾动作和停留目标。
7. 声音要求与具体失败排除。

时间码是期望约束，不是逐帧保证。少用无关负面词；精确文字、Logo、复杂 UI 等可能不稳定，应单独列为待验证目标。生成参数（实际模型 ID、模式、时长、分辨率、比例、seed等）单列，不把 Prompt 中“1080P”当接口已设置。

## 声音与素材包

要求原音乐就保留独立音轨及源起点。工具支持音频参考时才按其格式提交；不支持时明确要另行合成或交给用户处理。不可把“请用原音乐”一句当作音频已输入。视频素材的原声要不要静音按用户要求，不一律删除。

最终交付至少含：母版、实例、实际参考资产清单、请求参数、音频计划、未验证限制。实际提交后保存原文；后续整理版另行标记，不能回写成历史提交记录。
