# 对标视频 → 可复用生成提示词

> 作者：胡峻  
> Copyright © 2026 胡峻。保留所有权利。

本包独立完成“读懂参考 → 提炼机制 → 设计变化 → 选择参考方式 → 写母版与实例 → 按结果返修”。不依赖其他 Skill、私人工作区、指定账号或知识库。默认中文沟通，产品名与 API 字段保持原文。

## 开始时

先从用户消息与已有素材确定：参考在哪里，要保留和替换什么，只写提示词还是实际生成，是否保留原声。已有决定直接沿用；普通实现细节自行判断，只有缺少会实质改变结果的信息才提问。

- 用户只要分析或提示词，就完成这些内容，不自动发起收费生成。
- 用户要求生成，使用其已经配置、授权的工具。默认可优先考虑用户所称 SD 2.5 / Seedance 2.5；具体模型 ID、模式、分辨率、时长和参考能力以实际工具为准，不猜接口，不强制购买服务。
- 用户明确指定模型或剪辑/代码路线时沿用。生成、剪辑、代码合成是不同实现，不暗中替换。
- 将结果保存到用户选定位置；没有指定时放当前项目的独立案例目录。保留源素材和历史版本，不要求外部归档或维护全局账本。

## 能力不足时怎么做

先检查当前宿主是否能实际读取视频、图片和音频。用户给链接时，用现有浏览/下载工具读取可访问原片；不要把链接文字当视频内容。登录受限就请用户提供视频文件；读取登录 cookies 需要用户明确授权，不复制凭据。

有完整视频查看能力时看全片；只有抽帧工具时可分析可见画面，转场需加密抽帧，运动连续性与声音仍要标注限制。拿不到原片时不编造拆解，可以列出缺少的材料和基于用户描述的暂定提示词，并标“未看原片”。可用工具和无工具替代方案见 [references/media-tools.md](references/media-tools.md)。

## 工作顺序

### 1. 拆解原片

读取 [references/analyze-reference.md](references/analyze-reference.md)，检查完整片及关键转场。产出媒体信息、事件表和效果机制；结论要对应时间码或可见证据。区分直接观察、测量、推断与未知。

不要只列“黑底、霓虹、四个场景”。解释哪个动作发起变化、何时完成、镜头怎样衔接、声音为何在这里落点。不要凭少量截图固定段数，也不要从成片声称获得原工程的图层或精确曲线。

### 2. 提炼固定机制和替换槽

用一句话说明模板的核心效果，列出：

- 必须保留的关系：例如转身触发换装、脚落地时地图停止、重音与颜色闪变同刻。
- 可以更换的内容：人物、场景、服装、产品、文案、标识等。
- 本次改进：只根据用户目标或实测问题提出，不把原片缺点也固定下来。

没有真实表现数据时，只能讨论吸引力假设，不能声称复制了爆款因果机制。

### 3. 选择生成路线并写提示词

读取 [references/write-prompts.md](references/write-prompts.md)。判断 T2V、I2V、多参考路线和垫图是否必要；给实际使用的每份素材分配角色。原视频可只用于分析，不一定送入模型。

交付“参数化母版”和“填好所有变量的本次实例”。如果需要垫图，一并给出图像提示词；没有生成图就标记待制作，不能把计划写成已上传资产。

### 4. 可选试生成与返修

实际调用只限当前授权范围。保存提交原文、参数、资产角色、任务 ID、输出与版本；结果未知先查状态，不重复付费提交。不要因失败无限抽卡或扩大预算。

有输出后使用 [references/review-and-example.md](references/review-and-example.md) 对照。先定位偏差，再针对相关段落修改；延长时长、加更多参考或重抽都不是通用修复。

### 5. 交付

完整请求交付四项，局部请求按范围裁剪：

1. 拆解：事件表、核心机制、证据与未知。
2. 新方案：固定项、替换项、路线及选择理由。
3. 提示词包：母版、本次实例、素材依赖、请求参数和声音方案。
4. 验证状态：仅写好 / 已提交 / 已生成 / 已检查 / 用户认可；没做的不能写通过。

一份样片成功不代表任何素材都可复用。说明哪些槽位已实际测试、哪些还只是设计上的可替换。

用户未要求剪辑时，不自行启动剪辑软件或 Nemo；需要改走确定性时间轴时先说明理由，由用户决定。外部上传、发布和入库只在用户授权具体结果后进行；技术检查通过不等于用户审美通过。本包本身不连接任何外部内容库。
